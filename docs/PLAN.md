# 기획 질문과 개발 계획

## 현재 상태

`rhythm-game-development`를 메인 저장소로 사용하며 `rhythm-game2`는 보존합니다. 기존 게임 코드와 README를 유지하고, 준비 단계의 하네스를 현재 코드에 맞게 조정했습니다. 아래 구현 정보는 `index.html`, `assets/css/styles.css`, `assets/js/game.js`, `assets/js/firebase.js`를 읽어 확인한 내용입니다. 브라우저 실행이나 실제 플레이 테스트 결과를 뜻하지 않습니다.

## 코드에서 확인한 구성과 남은 질문

| 항목 | 현재 코드에서 확인한 내용 | 남은 결정·검증 질문 |
| --- | --- | --- |
| 플랫폼 | 브라우저에서 실행하는 웹 게임, Canvas 화면 | 지원할 브라우저·운영체제·기기와 모바일 지원 범위는 미확정입니다. |
| 개발 도구 | HTML, CSS, JavaScript, Canvas, Web Audio API. README에는 Python 로컬 서버 실행법이 있습니다. | 사용할 편집기, Python 버전, 표준 개발·검증 환경은 미확정입니다. |
| 조작 키 | 기본 A / S / K / L, 설정에서 레인 키 변경. Enter / Space로 화면 이동·시작, 방향키로 곡 선택, Esc로 일시정지·복귀. `touchstart` / `touchend` 레인 입력 처리도 있음 | 키 변경, 반복 입력, 동시 입력과 실제 입력 지연이 의도대로 동작하나요? |
| 노트 방식 | 4레인 일반 노트와 길게 누르는 롱노트. 곡별 EASY / NORMAL / HARD 노트맵 | 일반·롱노트 판정과 난이도별 배치가 의도에 맞나요? |
| 음악 | `SONGS`에 내장 MP3 4곡과 Web Audio 합성 음악 4곡. 곡별 길이·BPM·노트맵 정의 | 음악·자산의 사용 및 배포 권한은 미확인입니다. 각 곡의 실제 길이·박자·동기화는 확인이 필요합니다. |

곡 선택 난이도와 판정 모드는 별도 설정입니다. 코드의 판정 모드별 PERFECT / GOOD 값은 EASY 150 / 250ms, NORMAL 100 / 200ms, HARD 60 / 130ms이며 MISS 값은 모두 80ms입니다. 실제 입력 선택은 `handlePress`에서 GOOD 값의 1.5배까지 검사하므로, 이 표기값만으로 실제 경계를 확정하지 않습니다.

추가 검증 질문:

- 시작과 결과 화면의 RETRY(다시 하기) → 곡 선택 → START 흐름에서 시간, 노트, 점수·콤보와 눌린 키 상태가 모두 초기화되나요?
- 노트 시간은 `requestAnimationFrame` 시간, 음악은 `AudioContext` 시간을 사용합니다. 초반·중간·후반과 화면 갱신 속도 변화에서 오차가 누적되나요? 싱크 설정은 어떤 범위를 보정하나요?
- 일시정지 시 음악을 멈추고 재개 시 게임 시간을 조정하는 흐름에서 음악도 같은 위치로 이어지나요?
- `handlePress`의 입력 허용 범위와 `autoMiss`의 80ms 초과 처리가 이른 입력·늦은 입력에 어떤 결과를 만드나요? 롱노트 해제 경계도 의도와 일치하나요?
- `registerJudgement`의 PERFECT +100점, GOOD +50점·각 콤보 +1, MISS 콤보 초기화가 일반 노트와 최종 결과에서 일치하나요? 롱노트 시작은 `held` 상태로 전환되고, 홀드 중 100ms 이상 간격마다 +5점과 끝 판정이 별도로 처리됩니다. 이 흐름의 점수 합계도 맞나요?
- 일반적인 곡 완료 조건은 모든 노트 생성·처리 완료 또는 등록 곡 길이 +1000ms 경과입니다. HP 소진 시 실패 연출 후 종료하는 경로도 있습니다. 오디오 종료 이벤트 기준이 아니므로 실제 음악 끝, 남은 노트, 결과 화면 전환이 맞나요?
- Firebase 인증·데이터 연동과 개발 모드의 범위는 어떻게 검증하고 운영할까요?

위 질문은 코드로 찾은 확인 지점이며, 실제 결함으로 확정한 내용은 아닙니다.

## 단계별 개발 계획

1. **현재 상태와 목표 확인**: 기존 기능·실행법을 읽고, 위 질문 중 다음 작업의 범위와 기대 동작을 사용자와 정합니다. 미확정 사항을 임의로 결정하지 않습니다.
2. **검증 환경 준비**: 브라우저·운영체제·입력 장치와 실행 방법을 기록합니다. 음악·외부 서비스 접근 조건도 확인합니다.
3. **시작·재시작과 입력 검증**: 기존 기능을 먼저 실행해 초기화, 반복·동시 입력, 키 설정, 입력 지연을 확인합니다.
4. **음악·노트와 일시정지 검증**: MP3·합성 곡, 난이도와 싱크 설정별로 초반·중간·후반 및 일시정지 후 동작을 확인합니다.
5. **판정·점수·종료 검증**: 각 경계 직전·경계값·직후, 일반·롱노트, 점수·콤보와 음악 종료를 확인합니다.
6. **작은 개선**: 검증 결과와 사용자 요청을 근거로 한 번에 작은 기능이나 문제 하나를 수정하고, 영향받은 동작을 다시 확인합니다. 파일 삭제·큰 구조 변경은 먼저 물어봅니다.
7. **별도 검토와 기록**: 작성과 별도의 검토에서 코드·문서의 모순을 확인하고 `CHECKLIST.md`에 환경·방법·실제 결과·미확인 범위를 기록합니다. 요청받았을 때만 커밋·업로드합니다.

실행 확인 전에는 체크 항목을 완료로 표시하지 않습니다.
