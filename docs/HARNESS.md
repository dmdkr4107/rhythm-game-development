# 개발·테스트 에이전트 하네스

이 하네스는 프로젝트용 Codex 에이전트 정의, 역할 간 인계 절차, 자동 검사 명령으로 구성한다. 게임 기능은 변경하지 않는다.

개발과 테스트의 실행·인계·재시도는 메인 에이전트가 이 지침에 따라 조율한다. `scripts/Test-Game.ps1`은 검사 실행기이며 스크립트 단독으로 에이전트를 생성하거나 코드를 자동 수정하지 않는다.

## 구성

| 담당 | 정의 | 책임 |
| --- | --- | --- |
| 메인 에이전트 | 루트 `AGENTS.md`와 이 문서 | 범위·승인 확인, 역할 배정, 충돌 예방, 결과 통합 |
| 개발 에이전트 | `.codex/agents/game_developer.toml` | 작은 구현, 자체 검사, 변경 인계 |
| 테스트 에이전트 | `.codex/agents/game_tester.toml` | 실제 diff 검토, 독립 검사, 실패 재현과 미확인 범위 보고 |

모델과 추론 수준은 고정하지 않고 부모 설정을 따른다. 권한과 샌드박스도 부모에서 상속한다. 테스트 담당의 제품 코드 수정 금지는 역할 지침이며 운영체제 수준의 읽기 전용 격리는 아니다.

## 사용법

프로젝트를 연 Codex에 다음처럼 요청한다.

> 개발 에이전트 game_developer와 테스트 에이전트 game_tester를 사용해서 [작업 내용]을 진행해 줘. 기존 변경을 보존하고, 구현 후 독립 테스트가 실패하면 원인을 수정해 다시 검증해 줘. 최초 테스트를 포함해 최대 3회만 진행하고, 통과하면 종료해 줘. 미해결 오류와 미확인 항목은 따로 보고하고 업로드하지 마.

에이전트 파일이 목록에 보이지 않으면 프로젝트를 새 Codex 세션에서 연 뒤 다시 요청한다. 사용자 정의 역할을 지원하지 않는 환경에서는 메인 에이전트가 TOML의 지침을 일반 하위 에이전트에게 직접 전달한다. 하위 에이전트 실행 자체가 불가능하면 한 세션에서 개발과 검토 단계를 나누고 독립 에이전트 검증은 미실행으로 보고한다.

## 작업 순서와 파일 소유권

1. 메인 담당이 Git 상태, 관련 diff와 지침·계획·체크리스트를 읽고 요청 범위, 기대 동작, 기존 변경을 기록한다.
2. 개발 담당에게 목표와 수정 가능한 파일을 지정한다. 테스트 담당은 먼저 읽기만으로 검증 계획을 만들 수 있지만 구현 중 검사는 시작하지 않는다.
3. 개발 담당은 작은 변경과 자체 검사를 마친 뒤 수정 파일·함수·재현 방법·자체 검사 결과를 인계하고 편집 정지를 명시한다. 자체 검사는 독립 테스트 회차에 포함하지 않는다.
4. 메인은 인계와 편집 정지를 확인하고 회차, 검증 대상 변경 파일 목록과 기준 상태(관련 diff 또는 파일 해시)를 기록한 뒤 별도 테스트 담당에게 독립 검증을 지시한다. 검증이 끝날 때까지 대상 파일을 수정하지 않는다. 대상 변경을 발견하면 해당 결과를 통과로 처리하지 않고 메인에게 알린다. 테스트 작성이 필요하면 검증 전에 메인이 tests/의 구체적인 파일을 배정하고 작성 후 확정한 대상을 기록한다.
5. 필요한 검사가 모두 통과하면 조기 종료한다. 실패하면 메인이 파일/함수, 재현 절차, 예상 결과, 실제 결과, 실행 명령·종료 코드와 영향을 개발 담당에게 전달한다. 개발 담당은 원인을 확인해 수정하고 자체 검사와 재인계를 마친다. 메인은 다음 회차를 기록하고 별도 테스트 담당에게 재검증을 맡긴다.
6. 최초 독립 테스트가 1회차이며 최대 3회다. 초기 구현 1회와 실패 후 수정 최대 2회에 해당한다. 3회째 실패하면 추가 수정이나 4회 검증 없이 중단하고 미해결 오류를 보고한다. 회차는 메인이 소유하며 같은 작업의 세션 재시작·담당 교체로 초기화하지 않는다.
7. 환경 제약·실행 불가·미정 정책·승인 필요는 검사 실패와 구분해 미확인으로 기록한다. 이를 해결하려고 정책을 임의로 확정하거나 위험한 수정을 하지 않는다. 안전하게 진행할 수 없으면 중단 사유와 필요한 다음 조치를 보고한다. 필요한 검사를 실행하지 못했다면 통과가 아니며, 테스트 삭제·완화·스킵으로 성공시키지 않는다.
8. 메인 담당이 최종 diff를 검토하고 `docs/CHECKLIST.md`에 환경·실제 결과·미확인을 기록한다. 중요한 실패나 필요한 검사의 미확인이 남으면 완료로 표시하지 않는다. 에이전트 실행 여부와 검사 결과도 구분한다.

파일 삭제·큰 구조 변경은 AGENTS.md에 따라 사용자에게 먼저 묻는다. 판정·점수 등 미정 정책은 임의로 확정하지 않는다. 커밋·push·외부 업로드는 별도 요청이 있을 때만 한다.

## 자동 검사

PowerShell에서 다음을 실행한다. 실행 정책으로 차단되면 정책을 임의로 우회하지 말고 아래 개별 명령을 사용한다.

```powershell
./scripts/Test-Game.ps1
```

```powershell
node --check assets/js/game.js
node --check assets/js/firebase.js
node tests/static-check.mjs
node tests/game-regression.mjs
```

실행기는 검사 하나라도 실패하면 중단하며 실패를 성공으로 덮지 않는다. 물리 입력 지연, 청각적 싱크, 실제 브라우저의 시작·정지·재개, 성능과 Firebase 계정 연동은 이 자동 검사만으로 확인할 수 없다. +81ms 판정 처리 순서 차이 검사는 현재 문제를 재현하는 검사다.

## 인계·결과 양식

메인은 작업별로 다음 표를 복사해 실제 수행한 회차만 기록한다. 미사용 회차를 실행한 것으로 채우지 않는다. 회차 내 개별 검사와 개발 자체 검사는 별도 명령 결과로 남긴다.

| 독립 테스트 회차 (최대 3) | 개발 담당·테스트 담당 | 검증 대상 변경 목록·기준 diff/해시 | 실행 명령·종료 코드·근거 | 통과/실패/미확인 | 실패 원인·수정 내용·다음 조치 |
| --- | --- | --- | --- | --- | --- |
| 1 (최초 구현 후) | 실제 담당 기록 | 실제 파일 목록과 기준 기록 | 실제 실행 결과 기록 | 실제 결과 기록 | 통과 시 종료 / 실패 시 원인 전달 |

2·3회차는 실패 후 실제로 재검증했을 때만 행을 추가한다. 검증을 시작한 회차는 미확인으로 끝나도 사용한 회차로 남기며 초기화하지 않는다. 실제 실패가 없으면 재시도 경로 확인을 위해 게임이나 테스트를 고의로 망가뜨리지 않는다.

```text
요청과 기대 동작:
독립 테스트 회차 / 총 사용 회차 (최대 3):
기존 Git 변경과 이번 수정 파일:
검증 대상 기준 diff 또는 해시 / 인계 완료·편집 정지 여부:
담당 및 편집 허용 파일:
변경 이유와 주요 함수:
재현 절차 / 예상 결과 / 실제 결과:
실행 환경·명령·종료 코드:
통과:
실패 (기존 문제 / 새 회귀):
미확인 및 이유:
승인이 필요한 변경과 다음 작업:
```

3회 실패 또는 안전하게 진행할 수 없는 경우에는 다음 양식으로 최종 미해결 내용을 보고한다.

```text
최종 상태 / 사용한 독립 테스트 회차:
중단 이유 (3회 상한 / 환경 제약 / 미정 정책 / 승인 필요):
미해결 오류 (기존 문제 / 새 회귀):
파일·함수 / 재현 절차 / 예상 결과 / 실제 결과:
실행 명령·종료 코드·실패 근거:
시도한 수정과 회차별 결과:
기존 기능·기존 변경 보존 확인:
미확인 항목과 이유:
필요한 결정·환경 / 다음 작업:
```

## 설정 근거와 검증 범위

[공식 사용자 정의 에이전트 문서](https://learn.chatgpt.com/docs/agent-configuration/subagents)에 따른 프로젝트 `.codex/agents/*.toml` 형식을 사용한다. 각 정의에 name, description, developer_instructions를 지정했다. 이 파일 생성만으로 현재 세션에서 자동 실행되었다고 간주하지 않는다. TOML 해석과 실제 에이전트 등록·실행 확인은 구분해 보고한다.

### 2026-10-19 구성 확인 결과

- 메인: PowerShell 실행기 파서 구문 검사와 CRLF를 허용한 `git diff --check` 통과.
- 독립 테스트 에이전트: Python 3.14.7 `tomllib`으로 두 TOML 해석 및 필수 문자열 필드 확인 통과. Node.js v24.21.0에서 개별 자동 검사 4개 모두 종료 코드 0.
- 실행기 직접 실행: PowerShell 실행 정책의 `PSSecurityException`으로 차단됨. 정책을 우회하지 않고 개별 Node 명령으로 검증함. 실행기 전체 실행과 첫 실패 시 중단 동작의 실제 실행은 미확인.
- 역할 정의와 협업 지침 검토에서 차단 결함 없음. 이번 독립 검사는 일반 하위 에이전트에게 테스트 역할 지침을 직접 전달해 수행했으며, Codex 사용자 정의 역할의 자동 등록·선택은 미확인.
- 기존 게임 코드와 앞선 미커밋 변경을 유지함. 실제 브라우저 플레이와 물리 입력 지연은 검사하지 않았고 커밋·업로드도 하지 않음.
